# Types, value vs reference: answers

## Conceptual

1. Assigning a value type copies the data itself, so the two variables are
   independent. Assigning a reference type copies the reference, so both variables
   point at the same object and see each other's changes.

2. A value type that is a field of a class lives on the heap inside that object, not
   on the stack. Elements of an `int[]` live on the heap as well, and value types
   captured by a closure or stored in a boxed form also end up on the heap. The
   guaranteed property is copy-by-value, not a storage location.

3. Two records are equal when their declared data members have equal values
   (value-based equality, generated by the compiler). Two plain class instances are
   equal only when they are the same reference, unless the class overrides `Equals`
   and `==`.

4. Boxing wraps a value type in a heap object so it can be used as a reference type.

```csharp
int n = 5;
object boxed = n;      // boxing
int back = (int)boxed; // unboxing
```

Each box is a heap allocation plus a copy, so boxing in hot paths adds GC pressure
and cost. Generic types like `List<int>` store the value type directly and avoid
boxing.

5. For a plain class with no overrides, all three compare reference identity: `==`,
   `Equals`, and `ReferenceEquals` all ask "is this the same object?". `string`
   overloads `==` and overrides `Equals` to compare contents, so for strings `==`
   and `Equals` are value comparisons, while `ReferenceEquals` still checks
   identity.

6. `string` is immutable, so a value never changes under you and strings can be
   compared and shared like values. `s.Replace("a", "b")` returns a new string with
   the replacement; the original `s` is unchanged.

7. Prefer a `struct` when the data is small, logically a single value, and ideally
   immutable (examples: a point, a date, a money amount). Two common guidelines:
   keep it small because it is copied on every assignment and argument pass, and
   avoid making it a large mutable struct, which is error-prone and can hurt
   performance.

8. Both pass by reference. `ref` requires the caller to initialize the variable
   before the call, and the method may read and reassign it. `out` does not require
   initialization by the caller, and the method must assign it before returning.

## Coding

9. Reference semantics:

```csharp
class Box { public int Value; }

var a = new Box { Value = 1 };
var b = a;        // copies the reference
b.Value = 99;
Console.WriteLine(a.Value); // 99, same object
```

10. Value semantics:

```csharp
struct Point { public int X; }

var a = new Point { X = 1 };
var b = a;        // copies the value
b.X = 99;
Console.WriteLine(a.X); // 1, independent copy
```

11. Records:

```csharp
record Person(string Name, int Age);

var p1 = new Person("Ada", 36);
var p2 = new Person("Ada", 36);
Console.WriteLine(p1 == p2); // True, value-based equality

var older = p1 with { Age = 37 };
Console.WriteLine(older);    // Person { Name = Ada, Age = 37 }
Console.WriteLine(p1.Age);   // 36, p1 is unchanged
```

12. `out` example:

```csharp
bool TryHalve(int n, out int result)
{
    if (n % 2 == 0)
    {
        result = n / 2;
        return true;
    }
    result = 0; // must be assigned before returning
    return false;
}

Console.WriteLine(TryHalve(10, out int r1) ? r1.ToString() : "odd"); // 5
Console.WriteLine(TryHalve(7, out int r2) ? r2.ToString() : "odd");  // odd
```
